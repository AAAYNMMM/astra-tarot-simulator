# 工程护栏与本地验证方案

## 1. 文档职责

本文档定义模块化、资料升级、历史迁移和发布过程中必须持续满足的工程护栏。

任务编号、依赖、状态和顺序以 `EXECUTION_CONTRACTS.md` 为准；本文件不维护第二套任务图。

目标是防止：

- 重构破坏现有行为；
- 已知技术债永久化；
- 知识资料和生成目录漂移；
- 随机和排序不可复现；
- 历史丢失或伪造可复现性；
- PWA缓存遗漏或混合版本；
- 本地服务器暴露内部文件；
- 盲测集泄露给日常开发；
- 验证结果与实际commit不匹配。

## 2. CWapi本地验证

本项目不使用GitHub Actions。真实运行环境的测试、浏览器回归和验收统一复用 `AAAYNMMM/CWapi` 本地Runner。

### 2.1 锁定规则

- 不创建、恢复、启用或依赖 `.github/workflows/`。
- 代码、数据、存储、缓存、启动器、生成文件或发布变更必须绑定完整40位commit SHA。
- 没有当前commit对应的终态CWapi RESULT，不得宣称本地验证通过。
- GitHub可合并、无冲突或代码审查通过不能替代本地结果。
- RESULT后受验证产物发生变化，旧RESULT立即失效。
- 纯文档变更可以不跑完整回归，但必须完成至少两轮交叉一致性检查。

### 2.2 统一入口

最终结构：

```text
automation/
├── validate.py
├── browser_smoke.py
├── quality-baseline.json
└── README.md
```

支持scope：

- `baseline`：当前测试、模块规模、依赖边界和已知技术债。
- `targeted`：当前叶子任务涉及的模块、数据或平台检查。
- `full`：全部自动测试、生成一致性、Doctor、浏览器、PWA和历史回归。

验证脚本不得修改源码，不得依赖人工交互，不得把大型日志、浏览器产物或盲测正文提交仓库。

### 2.3 RESULT证据

每个非纯文档任务至少记录：

- commit SHA；
- task_id；
- scope；
- 实际命令；
- RESULT状态；
- 自动测试摘要；
- 人工检查摘要；
- 修改文件；
- 关键产物哈希；
- 警告和未覆盖环境。

推荐执行序列：

```text
git_rev_parse
git_status
repository_automation: automation/validate.py --scope <scope>
collect_hashes
git_status
```

baseline、targeted和full不能互相冒充。

## 3. 已知技术债基线

`automation/quality-baseline.json` 保存重构前已知越界，不是永久豁免。

字段至少包括：

```json
{
  "path": "app.js",
  "metric": "lines",
  "value": 1528,
  "reason": "pre-modularization monolith",
  "introducedAtCommit": "...",
  "mustBeRemovedBy": "MOD-006A",
  "mayGrow": false
}
```

判定：

- 已登记旧债且未增长：WARN。
- 旧债增长：FAIL。
- 新增人工越界：FAIL。
- 未登记越界：FAIL。
- 已清除债务重新出现：FAIL。
- Phase M full验证时人工文件越界清单必须为空。

## 4. 本地服务器访问边界

目标规则：

- 只允许应用入口、`src/`、`assets/`、manifest、图标和必要PWA文件。
- 拒绝 `.git/`、`.github/`、`docs/`、`tests/`、`scripts/`、`automation/`、`.qa/`、隐藏文件和临时文件。
- 拒绝URL编码、双重编码、反斜杠和规范化后的路径穿越。
- 默认监听 `127.0.0.1`。
- 非本机监听显示明确安全警告。
- 生命周期接口执行Origin检查和启动时随机令牌验证。
- 使用适合原生ES Modules的Content Security Policy。
- 白名单、路径穿越、生命周期和CSP均有自动测试。

不要求构建产物目录，优先通过请求处理器白名单保持 `python run.py` 直接运行。

## 5. 确定性与随机契约

### 5.1 独立随机流

生产使用高质量系统随机源生成根种子，再通过稳定、版本化的派生算法生成：

```text
rootSeed
├── draw
├── orientation
└── rendering
```

要求：

- 抽牌只消费draw流。
- 正逆位只消费orientation流。
- 模板轮换只消费rendering流。
- 模板新增随机选择不得改变牌序和正逆位。
- 引擎不得散落调用 `Math.random()`。
- 测试可注入固定源或固定根种子。

### 5.2 稳定排序与数值

- 评分排序必须声明稳定次级键，默认使用稳定业务ID。
- 不依赖对象属性遍历的偶然顺序。
- 不使用本地化字符串排序决定推理结论。
- 权重、阈值、平局规则和派生算法全部版本化。
- `NaN`、`Infinity`、未定义分数和未定义排序必须失败。
- 相同输入、版本、artifact哈希和根种子产生相同结构化结果和渲染选择。

## 6. 静态知识单一来源与生成

人工主来源：

- 单张CardSemanticProfile；
- 单题QuestionProfile；
- 固定牌阵与关系图；
- 词典；
- 模板。

正式脚本生成：

- 轻量卡牌目录；
- 卡牌动态注册表；
- 轻量问题目录；
- 问题动态注册表；
- knowledge完整性清单；
- artifact manifest；
- PWA预缓存清单。

要求：

- 生成文件位于 `src/generated/` 或明确generated路径。
- 文件头记录来源、生成命令和生成器版本。
- 生成结果提交仓库并可稳定重建。
- 验证脚本检查生成结果是否过期。
- 人工不得直接修改生成文件。
- 过渡目录必须明确标记并在正式生成器接管后删除。
- 仓库不得保留第二套人工维护目录。

## 7. Artifact manifest与内容哈希

artifact manifest至少包含：

- repository commit；
- engine manifest hash；
- knowledge manifest hash；
- 卡牌模块哈希；
- 问题模块哈希；
- 词典和模板哈希；
- 随机派生和评分版本；
- PWA清单哈希。

版本字符串不能替代内容哈希。验证必须能发现“内容已改但版本未升”和“生成文件对应旧人工源”。

## 8. Schema、词典与质量校验职责

### 结构Schema

负责：

- 对象结构和必填字段；
- 业务ID、语义单元ID和引用格式；
- 数值类型与范围；
- 基础枚举和结构级引用。

### 词典与政策

负责：

- 主题、关系、逆位、维度、结论和禁止断言词典；
- 标签成员资格和同义词合并；
- 跨词典引用；
- 来源、现代化解释和冲突政策。

### 质量门禁

统一运行Schema、词典、来源、重复率、反例、跨牌边界和人工评分。不得在词典冻结前要求结构Schema预知全部语义成员资格。

## 9. 单牌资料治理

每张牌记录：

- 主要传统；
- 参考资料ID和章节；
- 项目现代化解释范围；
- 审查状态和日期；
- 稳定语义单元ID；
- 近义牌边界；
- 常见误读和禁止推断。

建立：

```text
docs/references/
├── bibliography.md
├── interpretation-policy.md
└── source-conflict-policy.md
```

禁止把来源不明网络牌义直接作为正式资料。

反例至少拒绝：

- 无依据具体事件；
- 必然成功或失败；
- 强制人物指认；
- 精确日期；
- 医疗、法律和投资确定性判断；
- 单关键词机械解释。

## 10. 最终盲测保管

- 开发集和普通回归集可以提交仓库。
- 最终盲测集不得提交本项目仓库。
- 盲测集保存在CWapi受控本地目录或独立保管位置。
- 仓库只保存Schema版本、样本数量、生成政策和内容哈希。
- CWapi不得把盲测正文写入普通日志。
- 结果保存汇总指标、评审分歧、评审版本和数据集哈希。
- 保留一套未用于当前版本调参的备用盲测集。
- 修改规则、资料、词典、权重或模板后，旧盲测结果失效。

## 11. 历史、备份与容量

完整历史系统必须支持：

- 全部和单条JSON导出；
- Schema、版本和artifact指纹；
- 导入前大小、结构、版本、数量、哈希和冲突验证；
- 导入预览；
- 完整导出与仅显示结果导出；
- 导入失败不破坏现有数据。

容量规则：

- 不静默 `slice` 删除记录。
- 初始建议上限500条完整记录，最终以真实大小测量。
- 接近配额时提示。
- 支持筛选和批量删除。
- 自动清理必须经用户明确授权。

明确三类承诺：

1. 同产物确定性。
2. 历史可审计。
3. 有旧产物和兼容支持时的跨版本重新计算。

不得仅凭版本字符串承诺任意未来版本可重算旧结果。

## 12. 错误与诊断安全

统一错误结构至少包含：

- 错误码；
- 严重级别；
- 可公开上下文；
- 用户消息；
- 恢复动作；
- 原始cause，仅保留于本地受控上下文。

要求：

- 诊断默认不包含问题正文、完整解读和历史正文。
- 错误上下文采用字段白名单，不使用事后黑名单清洗。
- 错误日志有数量、时间和容量上限。
- 导入限制总大小、数量、嵌套深度和字段类型。
- 导入文本安全转义，不直接注入HTML。
- 资料加载失败不得重抽。
- 历史保存失败不得阻断当前解读。

任务拆分和依赖见 `EXECUTION_CONTRACTS.md`。

## 13. Doctor与浏览器回归

Doctor最终通过：

```text
python scripts/doctor.py
```

至少检查：

- Python和启动器条件；
- 必要入口文件；
- 四套牌面和牌背；
- 卡牌、问题目录、资料和注册表；
- 业务ID和语义引用；
- 四牌阵及牌位未变；
- 动态导入路径；
- 生成文件、artifact manifest和缓存清单；
- 模块规模、技术债和依赖；
- 历史Schema、迁移版本和内容指纹；
- LICENSE和第三方声明。

输出 `PASS / WARN / FAIL`，失败使用非零退出码。

浏览器回归覆盖：

- 启动和准备页；
- 主题、问题、牌阵和牌面选择；
- 洗牌、发牌、单张和全部翻牌；
- 结果生成；
- 历史写入、读取和删除；
- 刷新与生命周期关闭；
- 应用壳离线重新打开；
- 默认牌组完整离线占卜；
- 动态加载牌义和问题资料；
- IndexedDB不可用降级；
- PWA更新与回滚。

浏览器回归由CWapi本地执行。

当前不增加GitHub Actions、图数据库、后端SQLite、账号、云同步、插件、自定义牌阵、自由文本问题或强制npm构建链。

具体任务顺序、父子状态和发布依赖见 `EXECUTION_CONTRACTS.md`，不得在本文件另建任务映射表。
