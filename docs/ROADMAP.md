# 项目开发路线图

## 1. 使用方式

本路线图定义完整任务目录、依赖和阶段验收。

- 实时状态以 `PROGRESS.md` 为准。
- 锁定边界以 `DECISIONS.md` 为准。
- 模块化任务以 `MODULARIZATION_PLAN.md` 为准。
- 数据任务以 `DATA_ARCHITECTURE.md` 为准。
- 单牌资料以 `CARD_DATA_STANDARD.md` 为准。
- 最终质量以 `ENGINEERING_GUARDS.md` 和 `FINAL_QUALITY_GUARDS.md` 为准。

### 1.1 任务前缀

| 前缀 | 范围 |
|---|---|
| `DOC` | 文档、决策和流程 |
| `MOD` | Phase M 模块化 |
| `TQ` | 单牌资料与数据契约 |
| `QP` | 预设问题与 QuestionProfile |
| `PO` | 牌位运算与 Observation |
| `MR` | 多牌关系推理 |
| `CL` | 结论、评分和冲突消解 |
| `TX` | 模板化文本输出 |
| `AU` | 随机、历史和审计 |
| `EV` | 评测和质量门禁 |
| `UI` | 界面接入 |
| `AX` | 无障碍 |
| `ERR` | 错误恢复与诊断 |
| `PLAT` | PWA 与平台生命周期 |
| `PERF` | 性能与资源预算 |
| `PWA` | 安装与离线资源管理 |
| `REL` | 发布稳定化 |

### 1.2 父任务与叶子任务

- 父任务只用于汇总，不能直接成为 `NEXT`。
- 只有没有未拆分子任务的叶子任务可以执行。
- 一个叶子任务必须能对应一个明确 commit、一组验收和一份 CWapi RESULT。
- 大型资料、问题、评测和发布任务进入执行前必须拆分。

## 14. 任务选择原则

后续 AI 只能选择：

1. `PROGRESS.md` 中的 `IN_PROGRESS` 叶子任务。
2. 没有进行中任务时选择唯一 `NEXT` 叶子任务。
3. 父任务必须先拆分，不能直接成为 `NEXT`。
4. 若任务阻塞，先处理阻塞原因或记录 `BLOCKED`。
5. 每个非纯文档任务必须绑定完整 commit 和对应 CWapi RESULT。

不得跳过 Schema、词典、评测协议和黄金样本，直接批量重写 78 张牌。
