# 项目开发路线图

## 1. 使用方式

本路线图定义完整任务目录、依赖和阶段验收。

- 实时状态以 `PROGRESS.md` 为准。
- 锁定边界以 `DECISIONS.md` 为准。
- 模块化任务以 `MODULARIZATION_PLAN.md` 为准。
- 数据任务以 `DATA_ARCHITECTURE.md` 为准。
- 单牌资料以 `CARD_DATA_STANDARD.md` 为准。
- 最终质量以 `ENGINEERING_GUARDS.md` 和 `FINAL_QUALITY_GUARDS.md` 为准。

### 1.2 叶子任务与父任务

叶子任务：

- 可以成为 `NEXT`。
- 对应明确范围、commit、验收和 CWapi RESULT。
- 只有依赖全部满足时才能开始。

父任务：

- 不能成为 `NEXT`，不能直接执行。
- 状态由必需叶子任务和父级验收派生。
- 状态只允许 `PARENT-PENDING`、`PARENT-IN-PROGRESS`、`PARENT-DONE`、`PARENT-BLOCKED`。
- 依赖父任务表示依赖其 `PARENT-DONE`。
- 顺序明确时优先依赖最后一个叶子任务。

## 14. 任务选择原则

后续 AI 只能选择：

1. `PROGRESS.md` 中的 `IN_PROGRESS` 叶子任务。
2. 没有进行中任务时选择唯一 `NEXT` 叶子任务。
3. 父任务必须先拆分，不能直接成为 `NEXT`。
4. 父任务状态只能由叶子任务和父级验收派生。
5. 若任务阻塞，先处理阻塞原因或记录 `BLOCKED`。
6. 每个非纯文档任务必须绑定完整 commit 和对应 CWapi RESULT。
7. 不得跳过 Schema、词典、评测协议、黄金样本和 `TQ-005`，直接批量重写 78 张牌。
