# 项目开发路线图

## 1. 使用方式

本路线图只负责阶段导航、任务目录和阶段出口。

- 产品与技术锁定：`DECISIONS.md`
- 任务编号、依赖、状态、验证和发布顺序：`EXECUTION_CONTRACTS.md`
- 当前现场和唯一下一任务：`PROGRESS.md`
- 领域要求：模块化、数据、工程、最终质量、引擎和单牌标准文档

若本文件与 `EXECUTION_CONTRACTS.md` 冲突，以执行契约为准。

## 2. 任务前缀

| 前缀 | 范围 |
|---|---|
| `DOC` | 文档、决策和执行协议 |
| `MOD` | Phase M 模块化 |
| `TQ` | 单牌资料与跨域数据契约 |
| `QP` | 预设问题与 QuestionProfile |
| `PO` | 牌位运算与 Observation |
| `MR` | 多牌关系推理 |
| `CL` | Claim、评分、冲突和结构化校验 |
| `TX` | 模板化文本输出和渲染后校验 |
| `AU` | 随机、历史和审计 |
| `EV` | 评测、盲测和质量门禁 |
| `ERR` | 错误恢复与诊断 |

| `PERF` | 性能与资源预算 |
| `PWA` | 安装与离线资源管理 |
| `REL` | 发布稳定化 |

父任务状态由叶子任务派生，不能成为 `NEXT`。具体状态规则见 `EXECUTION_CONTRACTS.md`。

## 3. 阶段总览

| 阶段 | 名称 | 主要出口 |
|---|---|---|
| Phase 0 | 项目目标与执行系统 | 锁定边界、唯一执行契约和可靠任务现场 |

## 15. 任务选择原则

1. 优先执行 `PROGRESS.md` 中的 `IN_PROGRESS` 叶子任务。
2. 没有活动任务时执行唯一 `NEXT` 叶子任务。
3. 父任务不能直接成为 `NEXT`。
4. 任务进入 `NEXT` 前必须满足执行契约的就绪定义。
5. 每个非纯文档任务必须绑定完整commit和对应CWapi RESULT。
6. 不得跳过Schema、词典、评测协议、黄金样本和消费验证，直接批量重写78张牌。
7. 连续审查在两轮无新重大问题后停止，开始执行当前任务。
