# 最终质量收口与规划冻结

**状态：锁定**

## 1. 目的

本文件记录项目在现有模块化、数据架构、规则引擎和工程护栏之外的最后一组质量要求。它们用于保证更新可靠、界面可访问、故障可恢复、版本可兼容、评测可信以及资源占用可控。

本文件完成后，项目设计阶段正式收口。除非用户明确改变产品方向，不再继续增加平台型能力或新的前置规划；当前唯一下一任务仍是 `MOD-001`。

## 2. PWA 原子更新与正确回退

### PLAT-001：PWA 原子更新与资源类型回退

落地时机：`MOD-006`，最迟在 `REL-001` 前完成。

要求：

- 只有页面导航请求可以回退到 `index.html`。
- JavaScript、CSS、图片、卡牌资料和问题资料加载失败时必须返回正确失败，不得返回 HTML 冒充目标资源。
- 应用壳、引擎、静态知识、生成清单和缓存组使用同一发布版本标识。
- 新版本全部必要资源缓存成功后才能进入可切换状态。
- 当前存在未完成占卜时不得强制刷新或切换版本。
- 发现新版本时显示明确更新提示，由用户决定何时重新加载。
- 新版本确认可用前保留上一完整版本缓存；回滚完成后再清理失效缓存。
- 缓存安装、版本切换、旧缓存清理和离线模块加载必须有自动测试与 CWapi 本地回归证据。

验收：

1. 导航离线时可以回退首页。
2. 缺失模块不会被 HTML 替代。
3. 半完成缓存不会覆盖当前可用版本。
4. 占卜过程中不会被后台更新中断。
5. 更新失败后仍能启动上一完整版本。

## 3. 无障碍基线与动态牌桌回归

### AX-001：键盘、焦点和屏幕阅读器基线

落地时机：`UI-001` 前建立，`REL-001` 完成全量验收。

要求：

- 所有主要操作只使用键盘即可完成。
- 对话框打开后焦点进入有效区域，关闭后返回原触发按钮。
- 标签页使用 `tablist`、`tab` 和 `tabpanel` 语义，并支持合理方向键操作。
- 焦点样式始终清晰可见。
- 不以颜色、旋转或动画作为唯一信息来源。
- 页面放大到 200% 时仍可读取和操作。
- 高对比度、减少动画和常见屏幕阅读器模式下保持可用。

### AX-002：动态牌桌无障碍回归

要求：

- 每张未翻开和已翻开的牌都有可读名称、牌位、序号、正逆位和状态。
- 洗牌、发牌和翻牌状态通过节制的 live region 提示，不连续轰炸辅助技术。
- 单牌与综合标签切换后，焦点和朗读顺序保持正确。
- “全部翻开”、重新占卜、历史和确认流程均有键盘与屏幕阅读器回归。
- 触控目标尺寸和间距满足实际移动端操作需求。

验收证据由 CWapi 在真实浏览器环境执行并保存。

## 4. 统一错误、恢复和本地诊断

### ERR-001：统一错误模型与恢复流程

落地时机：基础接口可在 `MOD-004` 至 `MOD-006` 建立，完整实现不得晚于 `UI-001`。

标准错误至少包含：

```js
{
  code: "KNOWLEDGE_MODULE_LOAD_FAILED",
  severity: "recoverable",
  context: {
    cardId: "major-7",
    version: "1.2.0",
  },
  userMessage: "战车的详细资料未能加载。",
  recovery: ["retry", "reload"],
  cause: originalError,
}
```

要求：

- 动态模块、IndexedDB、迁移、缓存、备份导入和规则校验使用统一错误分类。
- 用户可执行的恢复动作必须明确，例如重试、刷新、返回准备页或导出诊断。
- 牌义或问题资料加载失败时保留已抽牌结果，不得重新抽牌或替换牌。
- 历史保存失败不得阻断当前解读。
- 导入文件必须限制总大小、记录数量、嵌套深度和字段类型。
- 所有导入文字必须安全转义，不得直接作为 HTML 注入。
- 本地诊断默认不包含用户问题、完整解读或历史正文；只有用户明确选择时才导出相关内容。
- 错误日志必须设置数量和容量上限，不得无限增长。

## 5. 版本兼容矩阵与回滚

### REL-005：版本兼容矩阵与回滚策略

落地时机：`AU-003` 后建立，`REL-004` 前必须完成。

需要分别管理：

- 引擎版本
- 卡牌 Schema 与资料版本
- 问题 Schema 与资料版本
- 词典与模板版本
- 存储 Schema 版本
- PWA 缓存与应用壳版本

要求：

- 建立机器可读兼容矩阵，声明允许组合、最低版本和不兼容组合。
- 历史记录保存本次实际使用的全部版本。
- 旧历史无法完整迁移时可以只读展示，不得伪造缺失证据链。
- 明确支持的迁移跨度；超出跨度时提供导出、只读或人工升级路径。
- 检测缓存、知识和引擎混合版本，发现后停止计算并进入恢复流程。
- 发布前保留上一稳定版本的回滚入口和数据兼容说明。
- 回滚不得破坏已经升级的用户历史；必要时以只读模式保护数据。

## 6. 评测治理与盲测

### EV-000：评测治理、盲测集和评审一致性

落地时机：基础规则在 `TQ-003` 前确定，最终盲测在 Phase 8 执行。

要求：

- 评测集分为开发集和冻结的最终盲测集。
- 最终盲测集不得为了迎合当前算法或资料结果随意修改。
- 单牌黄金样本至少由两位独立评审分别评分。
- 评审时隐藏旧版或新版来源，减少偏好影响。
- 评分差异超过预设阈值时进入复审，不直接取平均掩盖分歧。
- 每次评分保存分项、理由、评审版本和日期。
- 文笔流畅不能抵消牌义错误、问题偏离、证据缺失或越权断言。
- 评测必须覆盖六大领域、不同牌位、正位和多种逆位机制。
- 多牌测试必须包含冲突、修正、条件和趋势分散样本，不能只测试容易形成统一主题的牌组。
- 不得把最终盲测集用于日常规则调参。

9.0 以上表示在冻结量表和独立评审下达到目标，不是开发者自行宣布。

## 7. 性能、缓存和存储预算

### PERF-001：加载、缓存和存储预算

落地时机：Phase 8 建立测量基线，`REL-002` 完成发布验收。

要求：

- 初始启动只加载应用壳、轻量卡牌目录、轻量问题目录和必要配置。
- 单次占卜只加载抽中的 1、3、5 或 10 张详细牌义及当前问题配置。
- 规则计算不得长时间阻塞界面；若达到实际阻塞阈值，应切分任务或使用 Worker，但不预先引入复杂度。
- 单条 ReadingRecord、全部历史、导入文件和诊断文件均设置可测量的大小预算。
- 接近浏览器存储配额时提示用户，不静默删除历史。
- 性能目标以真实四种牌阵、四套牌面和目标历史规模测量，而不是空页面演示。

### PWA-002：安装图标与离线牌组管理

要求：

- 提供至少 192×192 和 512×512 的普通 PNG 图标。
- 提供具有安全留白的独立 maskable 图标，不把同一 SVG 同时假定为所有平台的最佳图标。
- 应用壳与 knowledge 缓存独立于四套牌面缓存。
- 默认不因缓存四套完整牌面而阻塞应用首次安装。
- 非默认牌组可以在首次选择时下载，并显示下载进度、完成状态和失败恢复。
- 用户可以删除单套牌面的离线缓存，但不得删除历史、设置或静态知识。
- 界面可显示各缓存组的大致占用空间和离线可用状态。

## 9. 规划冻结

自本文件建立后，开发方案视为足够完整。除非出现以下情况，否则不再增加新的规划阶段：

- 用户明确改变产品边界；
- 实现或测试证明现有架构无法满足锁定目标；
- 发现会造成数据丢失、安全暴露或核心功能不可用的阻断缺陷；
- 浏览器平台变化使既定方案无法继续运行。

不属于上述情况的想法进入发布后的候选清单，不得阻塞 2.0 路线。

当前明确不增加：

- 云同步和用户账户
- 插件市场或第三方规则包
- 自定义牌阵
- 自由文本问题
- 多语言系统
- 后端数据库
- 在线遥测
- 强制构建框架

项目下一步是执行 `MOD-001`，不是继续给蓝图增加装饰性塔楼。
