# 最终质量收口与规划冻结

**状态：锁定**

## 1. 目的

本文件记录模块化、数据架构、规则引擎和工程护栏之外的最后一组发布质量要求：更新可靠、界面可访问、故障可恢复、版本可兼容、评测可信、资源占用可控。

项目设计已收口。除非产品边界改变、实现证明架构不可行，或发现数据丢失、安全暴露和核心不可用等阻断问题，否则不再增加前置阶段。

## 2. PLAT-001：PWA原子更新与回滚

依赖：`MOD-006C`、`ERR-001`。

`MOD-006C` 只完成基础资源类型正确性：

- 仅导航请求可回退 `index.html`。
- JavaScript、CSS、图片和知识模块失败时不得返回HTML。
- 分组缓存和离线模块加载可验证。

`PLAT-001` 完成发布级能力：

- 应用壳、引擎、知识、清单和缓存组使用同一发布版本。
- 必要资源全部缓存成功后才允许切换。
- 未完成占卜时不强制刷新。
- 发现新版本时由用户决定重载时间。
- 新版本确认可用前保留上一完整版本。
- 更新失败后能够回滚。
- 自动测试和CWapi浏览器证据完整。

## 3. AX-001与AX-002：无障碍

### AX-001：基础无障碍

依赖：`ERR-001`，在 `UI-001` 前完成。

要求：

- 所有主要操作仅键盘可完成。
- 对话框焦点进入和返回正确。
- 标签页使用 `tablist`、`tab`、`tabpanel` 并支持方向键。
- 焦点样式始终可见。
- 不以颜色、旋转或动画作为唯一信息来源。
- 页面放大200%仍可操作。
- 高对比度和减少动画模式可用。

### AX-002：动态牌桌回归

依赖：`UI-001`。

要求：

- 每张牌有可读序号、牌位、名称、正逆位和状态。
- 洗牌、发牌和翻牌通过节制的live region提示。
- 标签切换后焦点和朗读顺序正确。
- 全部翻开、重新占卜、历史和确认流程可访问。
- 触控目标尺寸和间距适合移动端。

## 4. ERR-001：统一错误、恢复和诊断

基础接口可在Phase M建立；完整实现必须在 `UI-001` 前完成。

标准错误至少包含：

```js
{
  code: "KNOWLEDGE-MODULE-LOAD-FAILED",
  severity: "recoverable",
  context: {
    cardId: "major-7",
    version: "1.2.0",
  },
  userMessage: "战车的详细资料未能加载。",
  recovery: ["retry", "reload"],
  cause: originalError,
}
```

要求：

- 动态模块、IndexedDB、迁移、缓存、导入和规则校验使用统一分类。
- 恢复动作明确。
- 资料加载失败保留已抽牌结果，不得重抽。
- 历史保存失败不阻断当前解读。
- 导入限制总大小、记录数量、嵌套深度和字段类型。
- 导入文字安全转义，不直接注入HTML。
- 诊断默认不包含问题、完整解读和历史正文。
- 错误日志有数量和容量上限。

## 5. REL-005：版本兼容矩阵

依赖：`AU-003C`、`PLAT-001`。在 `REL-004` 前完成。

管理：

- 引擎版本
- 卡牌Schema和资料版本
- 问题Schema和资料版本
- 词典和模板版本
- 存储Schema版本
- 应用壳和PWA缓存版本

要求：

- 建立机器可读兼容矩阵。
- 历史保存实际使用版本。
- 无法完整迁移的旧历史可只读展示，不伪造证据。
- 明确支持的迁移跨度。
- 检测混合版本并进入恢复流程。
- 回滚不破坏已升级历史。

## 6. EV-000A与EV-000B：评测治理

### EV-000A：冻结评测协议

依赖：`TQ-002`，在 `TQ-003` 前完成。

要求：

- 区分开发集和最终盲测集。
- 冻结评分量表、独立评审流程和分歧阈值。
- 最终盲测集不得用于日常调参。
- 文笔不能抵消牌义错误、问题偏离、证据缺失或越权断言。

### EV-000B：执行最终盲测

依赖：`TQ-107`、`TX-003`，在Phase 8执行。

要求：

- 评审隐藏旧版或新版来源。
- 评分差异超过阈值进入复审。
- 保存分项、理由、评审版本和日期。
- 覆盖六领域、不同牌位、正位和多种逆位。
- 多牌样本包含冲突、修正、条件和趋势分散。

9.0以上必须来自冻结量表和独立评审，不是开发者自封。

## 7. PERF-001：性能与资源预算

依赖：`UI-001`、`AU-003C`。

要求：

- 初始只加载应用壳、轻量卡牌目录、轻量问题目录和必要配置。
- 单次只加载抽中的1、3、5或10张详细资料和当前问题配置。
- 规则计算不得长时间阻塞界面。
- ReadingRecord、全部历史、导入和诊断文件设置可测量预算。
- 接近存储配额时提示，不静默删除历史。
- 使用真实四牌阵、四套牌面和目标历史规模测量。

## 8. PWA-002：安装图标与离线牌组

依赖：`PLAT-001`、`PERF-001`。

要求：

- 提供192×192和512×512普通PNG图标。
- 提供独立maskable图标。
- 应用壳与knowledge缓存独立于四套牌面。
- 首次安装不因缓存四套完整牌面而阻塞。
- 非默认牌组按需下载并显示进度和失败恢复。
- 用户可删除单套牌面缓存，不删除历史、设置或知识。
- 显示缓存组大致空间和离线状态。

## 10. 规划冻结

不属于以下情况的想法进入发布后候选，不阻塞2.0：

- 用户明确改变产品边界。
- 实现或测试证明现有架构无法满足目标。
- 发现数据丢失、安全暴露或核心功能不可用。
- 浏览器平台变化使既定方案无法运行。

当前不增加云同步、账号、插件市场、自定义牌阵、自由输入、第三方规则包、后端数据库或复杂构建框架。
