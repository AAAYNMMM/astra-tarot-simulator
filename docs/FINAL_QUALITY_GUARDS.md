# 最终质量收口与规划冻结

**状态：锁定**

## 1. 文档职责

本文档定义发布级质量要求：更新可靠、界面可访问、故障可恢复、版本可兼容、评测可信、资源占用可控。

任务编号、拆分、依赖和发布顺序以 `EXECUTION_CONTRACTS.md` 为准；本文件不维护第二套任务图。

项目设计已收口。除非产品边界改变、实现证明架构不可行，或发现数据丢失、安全暴露和核心不可用等阻断问题，否则不再增加前置阶段。

## 2. PWA资源类型与离线状态

只有页面导航请求可以回退 `index.html`。JavaScript、CSS、图片和知识模块失败时不得返回HTML。

必须分别报告：

### `APP-SHELL-READY`

- shell、knowledge和默认启动配置可用。
- 应用能够启动并显示明确状态。
- 不等同于能够完成完整离线占卜。

### `DEFAULT-DECK-READY`

- 默认牌组必要牌面和牌背可用。
- 应用可以完成完整离线占卜。

### `SELECTED-DECKS-READY`

- 用户选择缓存的其他牌组可用。
- 单套牌组失败只影响该牌组，不破坏应用壳、默认牌组或当前稳定版本。

界面不得把“首页能离线打开”显示为“完整离线可用”。

## 3. PWA原子更新与回滚

发布级更新要求：

- 应用壳、引擎、知识、artifact manifest和缓存组使用同一发布版本。
- 必需资源完整缓存并校验后才允许切换。
- 任一必需资源失败时新版本不得激活。
- 活跃占卜期间不强制刷新。
- 发现新版本时由用户决定重载时间。
- 新版本确认可用前保留上一完整版本。
- 更新失败能够回滚。
- 混合版本被检测并进入恢复流程。
- 自动测试和CWapi浏览器证据完整。

## 4. 安装图标与离线牌组管理

要求：

- 提供192×192和512×512普通PNG图标。
- 提供独立maskable图标和安全区域。
- 应用壳、knowledge和牌组缓存彼此独立。
- 首次安装不因缓存全部四套牌面而阻塞。
- 非默认牌组按需下载并显示进度、空间、失败和恢复状态。
- 用户可删除单套牌组缓存，不删除历史、设置或知识。
- 默认牌组不可用时明确显示不能完成完整离线占卜。

## 5. 基础无障碍

要求：

- 所有主要操作仅键盘可完成。
- 对话框打开后焦点进入，关闭后返回触发控件。
- 标签页使用 `tablist`、`tab`、`tabpanel` 并支持方向键。
- 焦点样式始终可见。
- 不以颜色、旋转或动画作为唯一信息来源。
- 页面放大200%仍可操作。
- 高对比度和减少动画模式可用。
- 触控目标尺寸和间距适合移动端。

## 6. 动态牌桌无障碍

要求：

- 每张牌具有可读序号、牌位、名称、正逆位和状态。
- 洗牌、发牌和翻牌使用节制的live region提示。
- 不连续朗读每个装饰动画。
- 标签切换后焦点和朗读顺序正确。
- 全部翻开、重新占卜、历史、确认和恢复流程可访问。
- 动态错误和更新提示不会抢夺不必要的焦点。

## 7. 错误对象、恢复与诊断

统一错误至少包含：

```js
{
  code: "KNOWLEDGE-MODULE-LOAD-FAILED",
  severity: "recoverable",
  context: {
    cardId: "major-7",
    version: "1.2.0",
  },
  userMessage: "战车的详细资料未能加载。",
  recovery: ["retry", "reload"],
  cause: originalError,
}
```

要求：

- 错误码和严重级别稳定。
- 可公开上下文采用字段白名单。
- 动态模块、引擎、PWA、IndexedDB、迁移、导入和容量使用统一分类。
- 恢复动作明确且可测试。
- 资料加载失败保留已抽牌结果，不得重抽。
- 历史保存失败不阻断当前解读。
- 导入限制总大小、记录数量、嵌套深度和字段类型。
- 导入文字安全转义，不直接注入HTML。
- 诊断默认不包含问题正文、完整解读和历史正文。
- 错误日志有数量、时间和容量上限。

错误恢复任务的叶子拆分和依赖见 `EXECUTION_CONTRACTS.md`。

## 8. 版本兼容与artifact指纹

管理：

- 应用壳版本；
- 引擎和评分版本；
- 随机派生和洗牌版本；
- 卡牌Schema和资料版本；
- 问题Schema和资料版本；
- 词典和模板版本；
- 存储Schema版本；
- PWA缓存版本；
- artifact内容哈希。

要求：

- 建立机器可读兼容矩阵。
- 历史保存实际使用的版本和artifact指纹。
- 无法完整迁移的旧历史可只读展示，不伪造证据。
- 明确支持的迁移跨度。
- 检测混合版本并进入恢复流程。
- 回滚不破坏已升级历史。
- 版本字符串不能替代内容哈希。

明确三类承诺：

1. 同产物确定性。
2. 历史可审计。
3. 旧产物仍可获得且兼容时的跨版本重新计算。

## 9. 评测治理

### 开发集

- 可以提交仓库。
- 用于日常回归和调参。
- 必须有Schema、版本、来源和变更记录。

### 最终盲测集

- 不提交本项目仓库。
- 保存在CWapi受控本地目录或独立保管位置。
- 普通开发代理不得读取正文。
- 仓库只保存Schema版本、样本数量、生成政策和内容哈希。
- CWapi不得把正文写入普通日志。
- 保留一套未用于当前版本调参的备用盲测集。

### 独立评审

- 评审隐藏旧版或新版来源。
- 评分差异超过阈值进入复审。
- 保存分项、理由、评审版本、日期和数据集哈希。
- 文笔不能抵消牌义错误、问题偏离、证据缺失或越权断言。
- 覆盖六领域、不同牌位、正位和多种逆位。
- 多牌样本包含冲突、修正、条件和趋势分散。
- 修改规则、资料、词典、权重或模板后，旧盲测结果失效。

三项9.0以上必须来自冻结量表、受控数据集和独立评审，不是开发者自封。

## 10. 性能与资源预算

要求：

- 初始只加载应用壳、轻量卡牌目录、轻量问题目录和必要配置。
- 单次只加载抽中的1、3、5或10张详细资料和当前问题配置。
- 规则计算不得长时间阻塞界面。
- ReadingRecord、历史总量、导入和诊断文件设置可测量预算。
- 接近存储配额时提示，不静默删除历史。
- 使用真实四牌阵、四套牌面和目标历史规模测量。
- 生成清单、artifact manifest和缓存状态不得显著拖慢启动。
- 性能结果记录测试环境、浏览器、数据规模和阈值。

## 11. 浏览器支持矩阵

状态只允许：

- `SUPPORTED`
- `SUPPORTED-WITH-DEGRADATION`
- `NOT-TESTED`
- `NOT-SUPPORTED`

最终矩阵至少声明：

- Windows 10/11。
- Chrome、Edge、Brave当前稳定版。
- Firefox当前稳定版的核心功能和离线能力。
- Chromium PWA安装能力。
- Firefox安装能力的允许降级范围。
- 若继续声明移动端支持，Android Chrome与iOS Safari的测试范围。

未测试环境不得写成支持。浏览器版本更新后需要重新确认可能受影响的能力。

## 12. 最终全量回归

发布前最后一次完整回归至少覆盖：

- Python启动器和生命周期。
- 本地服务器访问边界。
- 准备、选择、洗牌、发牌、翻牌和结果。
- 78张牌、预设问题和四牌阵。
- 随机复现和稳定排序。
- Observation、Relation、Claim和双层安全校验。
- 历史写入、迁移、导入导出、容量和降级。
- artifact指纹和兼容矩阵。
- 应用壳、默认牌组和其他牌组离线状态。
- PWA更新和回滚。
- 无障碍和移动端。
- LICENSE和第三方声明。

最终回归之后若修改任何运行代码、数据、缓存、迁移、资源清单或生成产物，原结果立即失效，必须重新执行。

## 13. 规划冻结

不属于以下情况的想法进入发布后候选，不阻塞2.0：

- 用户明确改变产品边界。
- 实现或测试证明现有架构无法满足目标。
- 发现数据丢失、安全暴露或核心功能不可用。
- 浏览器平台变化使既定方案无法运行。

当前不增加云同步、账号、插件市场、自定义牌阵、自由输入、第三方规则包、后端数据库或复杂构建框架。

任务顺序和发布依赖见 `EXECUTION_CONTRACTS.md`，不得在本文件另建一套路线图。
