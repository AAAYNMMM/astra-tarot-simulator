# Phase 12：稳定性、精简解读与2.1.0

## 目标

Phase 12修复真实牌义导致的生成失败，移除全量资料预载和串行动画等待，并把默认输出收束为短、清楚、可追溯的解读。纯离线规则、固定问题、四种牌阵、公开ID和抽牌随机流保持不变。

## 解读契约

解读Schema为`4.0.0`，固定包含：

- `summary`：中文结论标签、一句话摘要和结果位证据；
- `keyEvidence`：2至4条不重复关键依据；
- `condition`：成立前提、停止信号和转折信号；
- `action`：一条可执行下一步；
- `cardEvidence`：每张抽牌一条结构化逐牌依据；
- `provenance`：Claim、结果位、证据数和可见文本规模。

所有可见块都必须具有稳定`evidenceRefs`。正常条件词不作为禁词；渲染校验只阻止无边界确定性断言、证据丢失、重复和错误标点。

## 性能与交互

- Worker只预热核心模块，当前QuestionProfile和抽中的CardSemanticProfile按需加载；
- 洗牌不超过900ms，发牌并行且总时长不超过800ms；
- 全部翻开批量执行，视觉错峰不超过1000ms，解读与翻牌动画并行；
- 减少动画模式取消非必要等待；
- 点击反馈小于100ms，开始到发牌完成P95小于2秒，翻开到摘要热启动P95小于1.5秒、冷启动P95小于2.5秒；
- 凯尔特规则计算P95小于50ms。
