# Phase 10：确定性解读与主线程解耦

## 用户反馈

- 删除设置页中的离线状态、版本、存储空间、页面状态、缓存和安全更新提示。
- 现有综合解读存在重复栏目、机械词、无效关系描述和固定三步建议。
- 最终结果需要在规则范围内给出唯一明确判断，不向用户输出模糊或未决结论。
- 完整推理必须离开 UI 主线程；页面只负责输入、动画和渲染。

## 输出模型

综合解读只保留：

1. 最终判断：唯一决断类型和一句直接判词。
2. 走势依据：只描述主导因果链，不复述最终判断。
3. 决定性牌位：最多三条，每条绑定具体牌位、牌和证据。
4. 改判条件：最多一条，说明哪项现实变化会改变当前规则结果；无条件时明确写“当前牌阵无改判条件”。

删除以下栏目和概念：

- 牌阵故事
- 牌与牌之间如何对话
- 你可以留意
- 接下来的三步
- 固定反思问题
- 固定“可撤回的小步骤”和“为不确定性保留空间”等套话

## 决断规则

- 最终 UI 不允许 `indeterminate`。
- 允许的最终动作域：`推进`、`有条件推进`、`等待`、`调整`、`停止`、`结束并转向`。
- 冲突不得导致未决；按候选净分、证据覆盖、关键牌位权重、来源顺序稳定决胜。
- 输出确定性仅表示同一输入在固定规则下得到唯一结果，不声明对现实未来具有客观必然性。

## 性能边界

- `application.js`、UI renderer 和 DOM 事件层不得直接导入完整 Reading Engine。
- 模块 Web Worker 负责资料加载、Observation、Relation、Claim、决断和文本结构生成。
- 主线程只发送可序列化输入并接收可序列化结果。
- Worker 失败显示明确错误，不在主线程静默重跑完整引擎。
- 卡牌动画必须批量读取布局后再写入动画，避免逐牌读写交错。

## 验收门禁

- 页面不存在离线状态面板及对应 DOM 必需绑定。
- 综合页不存在被删除栏目。
- 同一输入重复执行，结构化结果逐字节一致。
- 任意合法牌阵始终产生一个非未决判断。
- 综合结果段落之间无标准化重复句。
- 用户可见文本不得包含：`可能`、`也许`、`倾向`、`值得留意`、`继续观察`、`不宜作确定判断`。
- UI 主线程模块边界测试确认不直接执行完整 Reading Engine。
- Worker 协议、错误恢复、历史保存和四牌阵回归全部通过。
