# 项目决策记录

本文档保存已确认的产品与技术决策。后续开发不得凭临时偏好推翻。若用户明确改变方向，必须新增带日期的变更记录，并同步路线图和进度。

## D-001：运行时采用纯规则算法

**状态：锁定**

运行时不得调用 AI 大模型、在线推理 API 或云端生成式服务。牌义筛选、牌位转换、关系、结论、冲突和文本输出均由确定性规则完成。

## D-002：只允许固定预设问题

**状态：锁定**

不提供自由文本问题解析。每个问题拥有独立 `QuestionProfile`，声明回答维度、允许结论、禁止断言、时间范围和四牌阵适配。

## D-003：四种牌阵不得改变

**状态：锁定**

保留：心语单张、时间之流、五牌十字、凯尔特十字。不得新增、删除、重命名、重新排列牌位或改变现有牌位 ID。

## D-004：抽牌与解读严格分离

**状态：锁定**

抽牌先完成，解读后进行。问题、牌义和期望结果不得影响抽牌；不得隐藏重抽、替换或调整正逆位。

## D-005：三项核心质量目标均为 9.0 以上

**状态：锁定**

单牌资料、多牌综合和预设问题贴合度均须达到 9.0/10 以上。分数来自冻结量表、测试集和独立评审，不宣称科学验证的超自然预测准确率。

## D-006：单牌资料必须结构化

**状态：锁定**

每张牌至少包含原型、传统象征、正逆位机制、语义侧面、领域适配、可计算维度、关系标签、行动建议、来源和误读边界。

## D-007：牌位是运算符

**状态：锁定**

牌位必须改变语义选择、时态、主体、权重、条件和结论职责。Position Operator 参与 Observation 生成，不是生成后的提示文字。

## D-008：先结构化结论，再渲染文字

**状态：锁定**

先生成包含证据、反证、条件、置信度和分类的结构化对象，再由模板渲染。不得逐牌拼接说明段落冒充综合解读。

## D-009：关键牌位高于正逆位数量

**状态：锁定**

不得用正位数、逆位数、简单吉凶或单一元素直接决定总体结论。

## D-010：大阿卡纳不作为第五花色

**状态：锁定**

大阿卡纳独立分析原型、阶段和关键位置，不与四个 14 张花色直接比较数量优势。

## D-011：冲突必须解释

**状态：锁定**

依次尝试区分内外、先后、动机与条件、建议修正和条件分支。无法整合时输出趋势分散或不确定，不得删除反向证据。

## D-012：保持轻量、离线和可维护

**状态：锁定**

优先原生 JavaScript、Python 标准库、浏览器 IndexedDB/`localStorage`、Node 与 Python 测试。除非现有方案无法满足目标，否则不引入大型平台、图数据库、云服务或复杂构建链。

## D-013：代码必须模块化

**状态：锁定**

新规则引擎前完成 `MOD-001` 至 `MOD-006D`。JavaScript 人工文件 ≤ 600 行，CSS 人工文件 ≤ 900 行，入口建议 ≤ 200 行。不得建立新的单体文件。

## D-014：一张牌一个模块

**状态：锁定**

每张完整 `CardSemanticProfile` 独立文件；目录和注册表只保存轻量信息和加载映射；抽牌只依赖轻量目录。

## D-015：不引入强制构建步骤

**状态：锁定**

使用原生 ES Modules，`python run.py` 直接运行。用户不需要安装 npm 或先构建。开发生成文件必须提交仓库。

## D-016：可执行源码统一进入 `src/`

**状态：锁定**

应用、引擎、知识、存储、平台和样式统一放入 `src/`。根目录只保留入口、PWA 文件、资源、自动化、测试、脚本和文档。

## D-017：静态知识与用户数据分离

**状态：锁定**

卡牌、问题、牌阵、词典和模板放入 `src/knowledge/`；临时状态放入 `src/app/state/`；设置和历史通过 `src/storage/` 接口访问；引擎不得自行访问浏览器存储。

## D-018：详细资料按需加载

**状态：锁定**

卡牌和问题分别提供轻量目录，完整资料通过注册表动态导入并缓存。加载失败不得重抽、替换或使用错误资料。

## D-019：设置与历史分层存储

**状态：锁定**

小型设置使用 `localStorage`；完整历史和证据链使用 IndexedDB；控制器不得直接访问底层 API；IndexedDB 不可用时允许精简降级。

## D-020：历史保存结果快照，不复制知识库

**状态：锁定**

历史保存问题、牌阵、牌面、必要显示快照、随机、版本、Observation、Relation、Claim、校验和渲染结果，不复制整套知识库。

## D-021：缓存清单由脚本生成并分组

**状态：锁定**

缓存至少分 shell、knowledge 和四套牌面；动态模块进入完整性与缓存清单；单个可选资源失败不得使全部安装失败。

## D-022：不使用 GitHub Actions，统一采用 CWapi

**状态：锁定**

不创建、恢复或依赖 `.github/workflows/`。测试、构建、回归和真实验收由 `AAAYNMMM/CWapi` 本地 Runner 执行；任务绑定完整 40 位 commit SHA。

## D-023：本地服务器采用白名单和生命周期保护

**状态：锁定**

只允许应用入口、`src/`、`assets/` 和 PWA 文件；拒绝内部目录和隐藏文件；默认监听 `127.0.0.1`；非本机监听需警告；生命周期接口执行同源检查和随机令牌；增加适合 ES Modules 的 CSP。

## D-024：随机源可注入和测试

**状态：锁定**

生产使用高质量系统随机源；核心通过 `randomSource` 接收随机输入；测试可注入固定源；Phase M 只建立边界，不改变当前分布。

## D-025：目录、注册表和缓存清单单一来源生成

**状态：锁定**

完整卡牌、问题、牌阵、词典和模板是人工主来源；轻量目录、注册表、knowledge 清单和预缓存清单由脚本生成；生成结果提交且不得人工直接修改。

## D-026：单牌资料必须有来源、交叉边界和反例

**状态：锁定**

每张牌记录传统、参考资料、现代化解释范围、审查状态、日期、近义牌边界、常见误读和禁止推断。

## D-027：历史支持备份和容量管理

**状态：锁定**

支持全部和单条导出；导入前验证 Schema、版本、大小和冲突；失败不破坏现有历史；不静默截断；自动清理必须经用户授权。

## D-028：项目提供 Doctor 和浏览器回归

**状态：锁定**

提供 `python scripts/doctor.py` 和浏览器回归入口，由 CWapi 本地执行，不使用 GitHub Actions。

## D-029：发布前明确许可证和第三方声明

**状态：锁定**

发布前建立 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`。README 资源链接不能替代项目级许可证。

## D-030：业务 ID 统一并保持现有值

**状态：锁定**

卡牌、问题、牌阵和牌位业务 ID 使用现有小写 `kebab-case`，例如 `major-7`、`cups-two`、`career-change`、`cross`。Phase M 不得重命名现有公开 ID。

## D-031：推理证据引用稳定语义单元

**状态：锁定**

每条可进入推理的语义单元拥有稳定 ID。Observation、Claim 和历史使用 `cardId#semanticUnitId` 或等价稳定引用；文案润色不得破坏证据引用。

## D-032：只有叶子任务可以成为 `NEXT`

**状态：锁定**

父任务仅汇总，不能直接执行。单次叶子任务必须对应明确范围、commit、验收和 CWapi RESULT。

## D-033：统一验证入口从 `MOD-001` 开始

**状态：锁定**

`MOD-001` 建立 `automation/validate.py --scope baseline`；后续任务逐步扩展；`MOD-006D` 完成 `--scope full` 和 Phase M 终态回归。

## D-034：关系图先处理固定结构边

**状态：锁定**

关系计算顺序为：固定牌阵结构边 → 问题维度与牌位职责 → 主题、状态和行动关系 → 正逆位机制 → 元素、数字、宫廷和阶段辅助关系。不得对十张牌全部两两无差别建边。

## D-035：父任务状态由叶子任务派生

**状态：锁定**

父任务使用 `PARENT-PENDING`、`PARENT-IN-PROGRESS`、`PARENT-DONE`、`PARENT-BLOCKED`。父任务不能手工宣布完成；依赖父任务表示依赖其全部必需叶子任务完成和父级验收通过。

## D-036：前端拆分与服务器安全分开执行

**状态：锁定**

原 `MOD-004` 拆为：

- `MOD-004A`：状态、控制器和渲染器。
- `MOD-004B`：静态服务白名单、路径穿越、生命周期令牌、同源与 CSP。

两者属于不同风险面，必须独立验证。

## D-037：Schema 与词典校验职责分离

**状态：锁定**

`TQ-001` 负责对象结构、必填字段、ID/引用格式、数值范围和基础枚举；`TQ-002` 负责标签词典、成员资格、同义词合并和跨词典引用；`TQ-004` 统一运行完整质量门禁。

## D-038：随机流和排序必须确定

**状态：锁定**

根种子必须派生独立 `draw`、`orientation`、`rendering` 随机流。模板轮换不得消耗抽牌随机流。排序使用稳定次级键，不依赖对象遍历、本地化排序或未版本化平局行为。

## D-039：黄金样本先验证可消费性

**状态：锁定**

`TQ-004` 后、批量生产其余 72 张牌前执行 `TQ-005`。使用 6 张黄金样本、少量试验 QuestionProfile、现有牌位和最小 Observation 路径验证 Schema 真正可被引擎消费。

## D-040：最终盲测在测试集和门禁完成后执行

**状态：锁定**

`EV-000B` 必须依赖 `EV-001`、`EV-002`、`EV-003C` 和 `EV-004`，不得在测试集、自动指标或 Doctor 建立前执行。

## D-041：最终全量回归发生在所有发布前代码变更之后

**状态：锁定**

`REL-001` 是发布前最后一个完整代码回归任务。`REL-005`、PWA、性能、离线和兼容实现必须先完成；`REL-001` 后若修改运行代码，必须重新执行并取得新 CWapi RESULT。

## D-042：PWA 区分必需资源与可选资源

**状态：锁定**

shell、knowledge 和默认启动配置属于必需资源；四套牌面缓存属于可选资源组。必需资源失败时新版本不得激活；单套可选牌组失败只影响该牌组离线状态，不得破坏当前稳定版本。
