# 项目决策记录

本文档保存已确认的产品与技术决策。后续开发不得凭临时偏好推翻。若用户明确改变方向，必须新增带日期的变更记录，并同步执行契约、路线图和进度。

## D-001：运行时采用纯规则算法

**状态：锁定**

运行时不得调用 AI 大模型、在线推理 API 或云端生成式服务。牌义筛选、牌位转换、关系、结论、冲突和文本输出均由确定性规则完成。

## D-002：只允许固定预设问题

**状态：锁定**

不提供自由文本问题解析。每个问题拥有独立 `QuestionProfile`，声明回答维度、允许结论、禁止断言、时间范围和四牌阵适配。

## D-003：四种牌阵不得改变

**状态：锁定**

保留心语单张、时间之流、五牌十字、凯尔特十字。不得新增、删除、重命名、重新排列牌位或改变现有牌位 ID。

## D-004：抽牌与解读严格分离

**状态：锁定**

抽牌先完成，解读后进行。问题、牌义和期望结果不得影响抽牌；不得隐藏重抽、替换或调整正逆位。

## D-005：三项核心质量目标均为 9.0 以上

**状态：锁定**

单牌资料、多牌综合和预设问题贴合度均须达到 9.0/10 以上。分数来自冻结量表、测试集和独立评审，不宣称科学验证的超自然预测准确率。

## D-006：单牌资料必须结构化

**状态：锁定**

每张牌至少包含原型、传统象征、正逆位机制、语义侧面、领域适配、可计算维度、关系标签、行动建议、来源和误读边界。

## D-007：牌位是运算符

**状态：锁定**

牌位必须改变语义选择、时态、主体、权重、条件和结论职责。Position Operator 参与 Observation 生成，不是生成后的提示文字。

## D-008：先结构化结论，再渲染文字

**状态：锁定**

先生成包含证据、反证、条件、置信度和分类的结构化对象，再由模板渲染。不得逐牌拼接说明段落冒充综合解读。

## D-009：关键牌位高于正逆位数量

**状态：锁定**

不得用正位数、逆位数、简单吉凶或单一元素直接决定总体结论。

## D-010：大阿卡纳不作为第五花色

**状态：锁定**

大阿卡纳独立分析原型、阶段和关键位置，不与四个 14 张花色直接比较数量优势。

## D-011：冲突必须解释

**状态：锁定**

依次尝试区分内外、先后、动机与条件、建议修正和条件分支。无法整合时输出趋势分散或不确定，不得删除反向证据。

## D-012：保持轻量、离线和可维护

**状态：锁定**

优先原生 JavaScript、Python 标准库、浏览器 IndexedDB/`localStorage`、Node 与 Python 测试。除非现有方案无法满足目标，否则不引入大型平台、图数据库、云服务或复杂构建链。

## D-013：代码必须模块化

**状态：锁定**

新规则引擎前完成 Phase M。JavaScript 人工文件 ≤ 600 行，CSS 人工文件 ≤ 900 行，入口建议 ≤ 200 行。不得建立新的单体文件。

## D-014：一张牌一个模块

**状态：锁定**

每张完整 `CardSemanticProfile` 独立文件；目录和注册表只保存轻量信息和加载映射；抽牌只依赖轻量目录。

## D-015：不引入强制构建步骤

**状态：锁定**

使用原生 ES Modules，`python run.py` 直接运行。用户不需要安装 npm 或先构建。开发生成文件必须提交仓库。

## D-016：可执行源码统一进入 `src/`

**状态：锁定**

应用、引擎、知识、存储、平台和样式统一放入 `src/`。根目录只保留入口、PWA 文件、资源、自动化、测试、脚本和文档。

## D-017：静态知识与用户数据分离

**状态：锁定**

卡牌、问题、牌阵、词典和模板放入 `src/knowledge/`；临时状态放入 `src/app/state/`；设置和历史通过 `src/storage/` 接口访问；引擎不得自行访问浏览器存储。

## D-018：详细资料按需加载

**状态：锁定**

卡牌和问题分别提供轻量目录，完整资料通过注册表动态导入并缓存。加载失败不得重抽、替换或使用错误资料。

## D-019：设置与历史分层存储

**状态：锁定**

小型设置使用 `localStorage`；完整历史和证据链使用 IndexedDB；控制器不得直接访问底层 API；IndexedDB 不可用时允许精简降级。

## D-020：历史保存结果快照，不复制知识库

**状态：锁定**

历史保存问题、牌阵、牌面、必要显示快照、随机、版本、Observation、Relation、Claim、校验和渲染结果，不复制整套知识库。

## D-021：缓存清单由脚本生成并分组

**状态：锁定**

缓存至少分 shell、knowledge 和四套牌面；动态模块进入完整性与缓存清单；单个可选资源失败不得使全部安装失败。

## D-022：不使用 GitHub Actions，统一采用 CWapi

**状态：锁定**

不创建、恢复或依赖 `.github/workflows/`。测试、构建、回归和真实验收由 `AAAYNMMM/CWapi` 本地 Runner 执行；任务绑定完整 40 位 commit SHA。

## D-023：本地服务器采用白名单和生命周期保护

**状态：锁定**

只允许应用入口、`src/`、`assets/` 和 PWA 文件；拒绝内部目录和隐藏文件；默认监听 `127.0.0.1`；非本机监听需警告；生命周期接口执行同源检查和随机令牌；增加适合 ES Modules 的 CSP。

## D-024：随机源可注入和测试

**状态：锁定**

生产使用高质量系统随机源；核心通过依赖注入接收随机输入；测试可注入固定源；Phase M 只建立边界，不改变当前分布。

## D-025：目录、注册表和缓存清单单一来源生成

**状态：锁定**

完整卡牌、问题、牌阵、词典和模板是人工主来源；轻量目录、注册表、knowledge 清单和预缓存清单由脚本生成；生成结果提交且不得人工直接修改。

## D-026：单牌资料必须有来源、交叉边界和反例

**状态：锁定**

每张牌记录传统、参考资料、现代化解释范围、审查状态、日期、近义牌边界、常见误读和禁止推断。

## D-027：历史支持备份和容量管理

**状态：锁定**

支持全部和单条导出；导入前验证 Schema、版本、大小和冲突；失败不破坏现有历史；不静默截断；自动清理必须经用户授权。

## D-028：项目提供 Doctor 和浏览器回归

**状态：锁定**

提供 `python scripts/doctor.py` 和浏览器回归入口，由 CWapi 本地执行，不使用 GitHub Actions。

## D-029：发布前明确许可证和第三方声明

**状态：锁定**

发布前建立 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`。README 资源链接不能替代项目级许可证。

## D-030：业务 ID 统一并保持现有值

**状态：锁定**

卡牌、问题、牌阵和牌位业务 ID 使用现有小写 `kebab-case`，例如 `major-7`、`cups-two`、`career-change`、`cross`。Phase M 不得重命名现有公开 ID。

## D-031：推理证据引用稳定语义单元

**状态：锁定**

每条可进入推理的语义单元拥有稳定 ID。Observation、Claim 和历史使用 `cardId#semanticUnitId` 或等价稳定引用；文案润色不得破坏证据引用。

## D-032：只有叶子任务可以成为 `NEXT`

**状态：锁定**

父任务仅汇总，不能直接执行。单次叶子任务必须对应明确范围、commit、验收和 CWapi RESULT。

## D-033：统一验证入口从 `MOD-001` 开始

**状态：锁定**

`MOD-001` 建立 `automation/validate.py --scope baseline`；后续任务逐步扩展；`MOD-006D` 完成 `--scope full` 和 Phase M 终态回归。

## D-034：关系图先处理固定结构边

**状态：锁定**

关系计算顺序为：固定牌阵结构边 → 问题维度与牌位职责 → 主题、状态、行动和逆位语义关系 → 元素、数字、宫廷和阶段辅助关系。不得对十张牌全部两两无差别建边。

## D-035：父任务状态由叶子任务派生

**状态：锁定**

父任务使用 `PARENT-PENDING`、`PARENT-IN-PROGRESS`、`PARENT-DONE`、`PARENT-BLOCKED`。父任务不能手工宣布完成；依赖父任务表示依赖其全部必需叶子任务完成和父级验收通过。

## D-036：前端拆分与服务器安全分开执行

**状态：锁定**

状态、控制器和渲染器与静态服务白名单、路径穿越、生命周期令牌、同源和 CSP 属于不同风险面，必须独立验证。

## D-037：Schema 与词典校验职责分离

**状态：锁定**

结构 Schema 负责字段、ID、引用格式和数值范围；词典负责成员资格、同义词和语义引用；质量门禁统一运行完整校验。

## D-038：随机流和排序必须确定

**状态：锁定**

根种子必须派生独立 `draw`、`orientation`、`rendering` 随机流。模板轮换不得消耗抽牌随机流。排序使用稳定次级键，不依赖对象遍历、本地化排序或未版本化平局行为。

## D-039：黄金样本先验证可消费性

**状态：锁定**

黄金样本冻结后、批量生产其余 72 张牌前，必须冻结完整 QuestionProfile 和 Position Operator 契约，并通过消费者夹具和可消费性验证。

## D-040：最终盲测在测试集和门禁完成后执行

**状态：锁定**

最终盲测不得在测试集、自动指标、生产随机集成或 Doctor 建立前执行；盲测后修改引擎输入适配器、规则、资料、词典、权重或模板会使结果失效。

## D-041：最终全量回归发生在所有发布前变更之后

**状态：锁定**

`REL-001` 是发布前最后一个完整代码回归任务。其后若修改运行代码、数据、缓存、迁移、资源清单或生成产物，必须重新执行并取得新 CWapi RESULT。

## D-042：PWA 区分必需资源与可选资源

**状态：锁定**

shell、knowledge 和默认启动配置属于应用壳必需资源；牌组资源独立报告离线可用状态。单套牌组失败不得破坏当前稳定版本。

## D-043：执行顺序由唯一执行契约管理

**状态：锁定**

`docs/EXECUTION_CONTRACTS.md` 是任务编号、依赖、状态、验证和发布顺序的唯一执行来源。领域文档定义要求，但不得自行建立冲突的任务顺序。

## D-044：已知技术债采用单调收紧基线

**状态：锁定**

`MOD-001` 建立 `automation/quality-baseline.json`。已登记旧超限可以暂时产生 WARN，但不得增长；新超限、未登记越界或旧债增长必须 FAIL；`MOD-006D` 时人工文件超限清单清零。

## D-045：模块迁移采用渐进接线

**状态：锁定**

先建立 ES Module 入口和受控兼容桥，再逐步抽离并由真实应用使用模块；最后删除兼容桥、旧全局和旧大型文件。不得先制造未接线模块，最后一次性大爆炸切换。

## D-046：消费验证使用正式跨域契约

**状态：锁定**

批量牌资料前冻结正式 Card、Question 和 Position 契约；消费者夹具只能从正式契约抽取最小子集，不得自行发明与正式 Schema 不同的测试字段。

## D-047：Relation 任务顺序与运行优先级一致

**状态：锁定**

任务顺序固定为：结构边 → 问题维度与牌位职责 → 主题、状态、行动和逆位语义关系 → 辅助关系 → 正反例与复现测试。

## D-048：安全校验分为结构化与渲染后两层

**状态：锁定**

结构化 Claim 在进入模板前校验证据、问题维度、禁止结论、条件和冲突；渲染后再检查文本矛盾、禁止措辞、引用丢失、重复和格式。关键词扫描不能替代结构化校验。

## D-049：最终盲测集不得提交公开仓库

**状态：锁定**

最终盲测集保存在 CWapi 受控本地目录或独立保管位置。仓库只保存 Schema、数量、政策和内容哈希；普通开发代理不得读取盲测正文。

## D-050：历史与发布使用 artifact 指纹

**状态：锁定**

版本字符串不能单独证明产物相同。生成清单和 ReadingRecord 必须保存代码、引擎、知识、问题、词典、模板和缓存清单等内容哈希，以区分同产物确定性、历史可审计和跨版本重新计算。

## D-051：统一错误恢复拆为父任务

**状态：锁定**

错误恢复拆分错误对象与脱敏、运行时与 PWA 恢复、存储与迁移恢复、可复用恢复组件与诊断导出。恢复组件必须可由 fixture 独立测试，不依赖新版 UI 已完成接入。

## D-052：PWA 分别报告启动与完整离线能力

**状态：锁定**

PWA 分别报告 `APP-SHELL-READY`、`DEFAULT-DECK-READY` 和 `SELECTED-DECKS-READY`。可以离线打开应用壳不能冒充可以完成完整离线占卜。

## D-053：验证结果绑定产物并可失效

**状态：锁定**

每个非纯文档任务保存 commit、task_id、scope、测试摘要、人工检查和关键哈希。RESULT 后任何受验证代码或产物变化都会使旧结果失效。

## D-054：审查循环以收敛为目标

**状态：锁定**

连续审查最多执行用户指定轮数；连续两轮没有新的阻断级或重大执行问题时停止。不得为了凑轮数新增功能、阶段或非必要文档。

## D-055：原生 ESM 测试不引入 npm 构建

**状态：锁定**

Phase M 可以提交无依赖的 `package.json`，使用 `"type": "module"` 让 Node 直接导入浏览器 ESM。它不要求 `npm install`、不增加运行依赖，也不引入构建步骤。遗留 CommonJS 测试在迁移期使用 `.cjs`，最终测试入口统一并可由 `node` 直接运行。

## D-056：最终 CSP 不保留内联脚本或样式豁免

**状态：锁定**

当前动态 `style` 属性、CSSOM 内联样式和 HTML 字符串写入必须在服务器 CSP 强制前完成清单和迁移。最终发布不得依赖 `script-src 'unsafe-inline'` 或 `style-src 'unsafe-inline'`。持久化、导入或外部数据只能通过安全 DOM 写入路径进入页面。

## D-057：业务随机与平台熵彻底分离

**状态：锁定**

抽牌、正逆位和模板选择只使用版本化业务随机流。生命周期令牌、客户端 ID 和安全 nonce 使用平台高质量熵，不要求复现，也不得消费业务随机流。安全令牌不得降级为 `Math.random()`。

## D-058：Service Worker 按资源类型选择策略

**状态：锁定**

导航、版本化代码与知识、牌组图片和生命周期请求使用不同策略。生命周期端点和跨源请求不缓存；只缓存同源成功响应；错误、404和不受信任的 opaque 响应不得写入缓存；缓存写入必须绑定事件生命周期。

## D-059：内容哈希采用规范化算法

**状态：锁定**

artifact 使用 SHA-256。文本按 UTF-8 和 LF 规范化，结构化数据使用稳定键序，二进制按原始字节计算，路径按规范化相对路径排序。完整78张哈希留在 artifact manifest；ReadingRecord只保存总清单哈希和本次实际消费的卡牌、问题、牌阵、词典及模板指纹。

## D-060：生成产物必须随人工源变化同步更新

**状态：锁定**

正式生成器建立后，任何人工知识、引擎入口、词典、模板或缓存资源变化都必须重建对应目录、注册表、artifact manifest和预缓存清单。陈旧生成文件属于 FAIL，不能留给发布阶段再补。
