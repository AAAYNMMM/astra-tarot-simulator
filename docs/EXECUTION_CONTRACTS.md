# 项目执行契约

**状态：锁定**

本文档是任务编号、依赖关系、任务状态、验证证据和发布顺序的唯一执行来源。

其他文档继续定义产品边界、架构、数据标准和质量要求；若其他文档中的旧任务名称、旧依赖或旧阶段顺序与本文冲突，以本文为准，并在后续修改相关文档时清理旧表述。

---

## 1. 文档权威层级

按以下顺序解释冲突：

1. `docs/DECISIONS.md`：不可擅自改变的产品与技术决策。
2. `docs/EXECUTION_CONTRACTS.md`：任务编号、依赖、状态、验证和发布顺序。
3. `docs/PROGRESS.md`：当前活动任务、证据和唯一下一任务。
4. 领域规范：模块化、数据、引擎、单牌、工程和最终质量文档。
5. `docs/ROADMAP.md`：阶段导航和任务目录，不重复发明依赖。
6. `README.md`：面向使用者和开发者的概览。

领域规范不能自行改变任务顺序；路线图不能覆盖锁定决策；聊天记录不能覆盖仓库现场。

## 2. 任务状态与粒度

### 2.1 叶子任务

叶子任务可以成为 `NEXT`，必须同时具备：

- 唯一任务 ID；
- 明确依赖；
- 有限修改范围；
- 输入、输出和不变量；
- 自动与人工验收；
- 明确回滚或兼容方式；
- 一个可审计 commit；
- 适用的 CWapi RESULT。

状态只允许：

- `BACKLOG`
- `NEXT`
- `IN_PROGRESS`
- `BLOCKED`
- `DONE`

### 2.2 父任务

父任务不能成为 `NEXT`，不能直接执行或手工宣布完成。

状态只允许：

- `PARENT-PENDING`
- `PARENT-IN-PROGRESS`
- `PARENT-BLOCKED`
- `PARENT-DONE`

父任务状态由全部必需叶子任务和父级验收派生。依赖父任务表示依赖其达到 `PARENT-DONE`。

### 2.3 任务就绪定义

叶子任务进入 `NEXT` 前必须满足：

1. 所有依赖已完成。
2. 规范来源可定位。
3. 修改边界和禁止范围明确。
4. 需要保持的公开 ID、存储字段和行为已记录。
5. 测试入口和人工检查项已定义。
6. 兼容、迁移或回滚方式明确。
7. 不包含两个可以独立失败的主要风险面。

不满足以上条件的任务必须先拆分或补契约，不能边实现边猜。

### 2.4 任务完成定义

任务标记 `DONE` 前必须满足：

1. 产物已提交。
2. 验收项全部完成。
3. 代码、数据和生成文件一致。
4. 当前 commit 具有匹配的终态 CWapi RESULT，纯文档任务除外。
5. 必要人工基线或抽样已记录。
6. 没有破坏锁定边界、公开 ID 或存储兼容。
7. `PROGRESS.md` 保存完整现场和唯一下一叶子任务。

## 3. 验证证据契约

每个非纯文档叶子任务必须保存以下证据：

- 完整 40 位 commit SHA；
- CWapi task_id；
- RESULT 状态和验证 scope；
- 实际执行命令；
- 变更文件；
- 自动测试摘要；
- 人工检查摘要；
- 生成文件或关键产物哈希；
- 已知警告和未覆盖环境。

代码、数据、缓存、迁移或资源清单在 RESULT 后发生任何变化，旧 RESULT 立即失效。不能把前一个 commit 的成功结果贴到后一个 commit 上继续使用。

纯文档修改可以不创建 CWapi TASK，但必须完成至少两轮交叉一致性检查，并记录修改文档、冲突检查和唯一 `NEXT` 是否保持。

至少记录：

当前已知超限：

- 已登记旧超限且未增长：`WARN`。

baseline不是永久豁免，而是防止重构前的已知债务让第一个验证脚本永远失败。

## 5. Phase M：渐进式模块迁移

每个抽离模块必须立刻被真实应用使用和回归，不得先建立一批未接线的“展示模块”，最后再一次性切换。

### MOD-001：模块边界、数据边界与基线验证

产物：

- `docs/MODULE_MAP.md`
- `scripts/check_module_size.py`
- `scripts/check_import_boundaries.py`
- `tests/module_contract_test.js`
- `automation/validate.py`
- `automation/README.md`
- `automation/quality-baseline.json`
- 最小 `src/` 骨架或职责说明
- 旧历史、公开 ID、浏览器和人工流程基线

`automation/validate.py --scope baseline` 必须能够在已知技术债存在时通过，但任何增长、新债务或未登记越界必须失败。

### MOD-002：拆分 CSS

依赖：`MOD-001`。

将活动样式迁入 `src/styles/`。每次拆分后页面必须真实使用新文件，临时更新 PWA 资源列表，任一人工 CSS 不得超过 900 行。

### MOD-003A：建立 ES Module 入口与兼容桥

依赖：`MOD-001`。

目标：

- `index.html` 使用最小模块入口；
- 旧 `app.js` 和 `data.js` 可通过受控兼容桥继续运行；
- 新模块可以逐步替换旧职责；
- 兼容桥有明确删除条件；
- 当前行为、生命周期和离线启动保持不变。

禁止在本任务中拆完全部业务逻辑。

### MOD-003B：抽离基础模块

依赖：`MOD-003A`。

抽离 `config/`、`core/`、`platform/` 和基础 `storage/` 接口，包括随机依赖注入边界、资源路径、HTML转义、设置和生命周期客户端。抽离后的代码必须由真实入口调用。

### MOD-004A：拆分状态、控制器与渲染器

依赖：`MOD-003B`。

拆分应用状态、DOM引用、控制器和渲染器。准备、洗牌、发牌、翻牌、结果和历史交互必须等价。

### MOD-004B：本地服务器访问边界与生命周期保护

依赖：`MOD-003B`。

独立完成静态白名单、路径规范化与穿越测试、生命周期随机令牌、Origin检查、非本机监听警告和CSP。

### MOD-005：规范化人工知识源与旧版解读

依赖：`MOD-004A`。

目标：

- 迁移当前78张牌、42个问题和4种牌阵的人工主来源；
- 定义正式生成所需的轻量元数据；
- 保留旧版解读适配器；
- 任何临时目录或注册表明确标记为过渡产物；
- 当前结果和公开 ID 不变。

### MOD-006A：删除兼容桥、旧全局和旧大型文件

依赖：`MOD-002`、`MOD-004A`、`MOD-004B`、`MOD-005`。

删除兼容桥、`window.TarotData` 等旧全局和已被完全替代的大型文件。不是第一次接线任务，而是清理已经逐步运行验证过的兼容层。

### MOD-006B：正式生成目录、注册表和清单

依赖：`MOD-006A`。

正式生成：

- 轻量卡牌目录；
- 卡牌动态注册表；
- 轻量问题目录；
- 问题动态注册表；
- knowledge完整性清单；
- PWA预缓存清单；
- 内容哈希与artifact manifest。

删除或替换所有临时目录。仓库不得保留第二套人工维护目录。

### MOD-006C：PWA资源类型、等级与状态

依赖：`MOD-006B`。

只有导航请求可以回退 `index.html`。定义三种状态：

1. `APP-SHELL-READY`：shell、knowledge和默认配置可用，应用可启动。
2. `DEFAULT-DECK-READY`：默认牌组可用，可完成完整离线占卜。
3. `SELECTED-DECKS-READY`：用户选择缓存的其他牌组可用。

默认牌组失败不得伪装为完整离线可用；其他牌组失败只影响对应牌组。

### MOD-006D：Phase M终态验证

依赖：`MOD-006C`。

完成 `automation/validate.py --scope full`、浏览器回归、历史兼容、PWA离线和模块边界验证。人工文件超限技术债必须清零。通过后解除Phase 1阻塞。

### Phase M临时缓存规则

在 `MOD-006B` 接管正式生成前，每个新增并被真实入口使用的JS或CSS模块必须同步更新临时Service Worker资源列表和离线烟雾测试。不能等到Phase M末尾才发现离线缓存遗漏了半个应用。

## 9. 盲测数据保管

最终盲测集不得提交本项目仓库，也不得出现在普通AI可读取的开发资料中。

要求：

- 开发集和普通回归集可以提交仓库。
- 最终盲测集保存在CWapi受控本地目录或独立保管位置。
- 仓库只保存数据集Schema版本、样本数量、生成政策和内容哈希。
- CWapi通过受控参数读取盲测集，不把正文写入日志。
- 结果只保存汇总指标、评审分歧、评审版本和数据集哈希。
- 保留一套未用于本次版本调参的备用盲测集。
- 盲测后修改规则、资料、词典、权重或模板，原结果立即失效。

`EV-000B` 必须发生在 `EV-001`、`EV-002`、`EV-003C` 和 `EV-004` 完成之后。

## 10. Artifact指纹与历史承诺

`MOD-006B` 生成artifact manifest；`AU-002` 将指纹写入ReadingRecord。

至少保存：

```js
artifactFingerprint: {
  repositoryCommit: "...",
  engineManifestHash: "...",
  knowledgeManifestHash: "...",
  cardModuleHashes: {},
  questionModuleHash: "...",
  vocabularyHash: "...",
  templateHash: "...",
  cacheManifestHash: "...",
}
```

明确三种承诺：

1. 同产物确定性：相同输入、根种子、版本和哈希产生相同结构化结果。
2. 历史可审计：旧记录保存当时的结构化证据和显示文本，即使旧产物不再可执行也能查看。
3. 跨版本重新计算：只有旧引擎和旧知识产物仍可获得且兼容时才保证。

版本字符串不能单独替代内容哈希。

## 14. 审查循环与停止条件

用户明确要求连续审查时，最多执行用户指定轮数。每轮只允许产生以下结果之一：

- 新发现的阻断或重大冲突；
- 已有问题的修正；
- 交叉一致性验证；
- 无新问题。

停止条件：

1. 连续两轮没有发现新的阻断级或重大执行问题。
2. 唯一 `NEXT` 任务满足就绪定义。
3. 依赖图无循环、无跨阶段隐式前置契约。
4. 任务验证有明确成功与失败语义。
5. 不再通过新增非必要文档制造形式进度。

达到停止条件后应结束审查并开始执行当前任务，而不是为了凑轮数继续发明优化事项。
