# 项目执行契约

**状态：锁定**

本文档是任务编号、依赖关系、任务状态、验证证据和发布顺序的唯一执行来源。

其他文档继续定义产品边界、架构、数据标准和质量要求；若其他文档中的旧任务名称、旧依赖或旧阶段顺序与本文冲突，以本文为准，并在后续修改相关文档时清理旧表述。

---

## 1. 文档权威层级

按以下顺序解释冲突：

1. `docs/DECISIONS.md`：不可擅自改变的产品与技术决策。
2. `docs/EXECUTION_CONTRACTS.md`：任务编号、依赖、状态、验证和发布顺序。
3. `docs/PROGRESS.md`：当前活动任务、证据和唯一下一任务。
4. 领域规范：模块化、数据、引擎、单牌、工程和最终质量文档。
5. `docs/ROADMAP.md`：阶段导航和任务目录，不重复发明依赖。
6. `README.md`：面向使用者和开发者的概览。

领域规范不能自行改变任务顺序；路线图不能覆盖锁定决策；聊天记录不能覆盖仓库现场。

## 2. 任务状态与粒度

### 2.1 叶子任务

叶子任务可以成为 `NEXT`，必须同时具备：

- 唯一任务ID；
- 明确依赖；
- 有限修改范围；
- 输入、输出和不变量；
- 自动与人工验收；
- 明确回滚或兼容方式；
- 一个可审计commit；
- 适用的CWapi RESULT。

状态只允许：`BACKLOG`、`NEXT`、`IN_PROGRESS`、`BLOCKED`、`DONE`。

### 2.2 父任务

父任务不能成为 `NEXT`，不能直接执行或手工宣布完成。

状态只允许：`PARENT-PENDING`、`PARENT-IN-PROGRESS`、`PARENT-BLOCKED`、`PARENT-DONE`。

父任务状态由全部必需叶子任务和父级验收派生。依赖父任务表示依赖其达到 `PARENT-DONE`。

### 2.3 任务就绪定义

叶子任务进入 `NEXT` 前必须满足：

1. 所有依赖已完成。
2. 规范来源可定位。
3. 修改边界和禁止范围明确。
4. 需要保持的公开ID、存储字段和行为已记录。
5. 测试入口和人工检查项已定义。
6. 兼容、迁移或回滚方式明确。
7. 不包含两个可以独立失败的主要风险面。
8. 不依赖尚未冻结的隐式契约。

不满足以上条件的任务必须先拆分或补契约，不能边实现边猜。

### 2.4 任务完成定义

任务标记 `DONE` 前必须满足：

1. 产物已提交。
2. 验收项全部完成。
3. 代码、数据和生成文件一致。
4. 当前commit具有匹配的终态CWapi RESULT，纯文档任务除外。
5. 必要人工基线或抽样已记录。
6. 没有破坏锁定边界、公开ID或存储兼容。
7. `PROGRESS.md` 保存完整现场和唯一下一叶子任务。

## 3. 验证证据契约

每个非纯文档叶子任务必须保存：

- 完整40位commit SHA；
- CWapi task_id；
- RESULT状态和scope；
- 实际执行命令；
- 变更文件；
- 自动测试摘要；
- 人工检查摘要；
- 生成文件或关键产物哈希；
- 已知警告和未覆盖环境。

代码、数据、缓存、迁移或资源清单在RESULT后发生任何变化，旧RESULT立即失效。不能把前一个commit的成功结果贴到后一个commit上继续使用。

纯文档修改可以不创建CWapi TASK，但必须完成至少两轮交叉一致性检查，并记录修改文档、冲突检查和唯一 `NEXT` 是否保持。

## 9. 最终盲测数据保管

最终盲测集不得提交本项目仓库，也不得出现在普通AI可读取的开发资料中。

- 开发集和普通回归集可以提交仓库。
- 最终盲测集保存在CWapi受控本地目录或独立保管位置。
- 仓库只保存数据集Schema版本、样本数量、生成政策和内容哈希。
- CWapi通过受控参数读取盲测集，不把正文写入日志。
- 结果只保存汇总指标、评审分歧、评审版本和数据集哈希。
- 保留一套未用于当前版本调参的备用盲测集。
- 盲测后修改引擎输入适配器、规则、资料、词典、权重或模板，原结果立即失效。

`EV-000B` 必须发生在 `EV-001`、`EV-002`、`EV-003C` 和 `EV-004` 完成之后。

## 15. 审查循环与停止条件

用户明确要求连续审查时，最多执行用户指定轮数。每轮只允许产生新重大问题、问题修正、交叉验证或无新问题。

停止条件：

1. 连续两轮没有新的阻断级或重大执行问题。
2. 唯一 `NEXT` 满足就绪定义。
3. 依赖图无循环、无跨阶段隐式前置契约。
4. 验证有明确成功与失败语义。
5. 不再通过新增非必要文档制造形式进度。
