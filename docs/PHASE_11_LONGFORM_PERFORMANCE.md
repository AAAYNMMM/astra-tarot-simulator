# Phase 11：长篇因果解读与渲染性能

## 阶段目标

本阶段把 Phase 10 的唯一决断继续扩展为可阅读、可验证、非重复的长篇判词，同时恢复页面交互流畅度。目标不是增加模板数量，而是建立一份结构化论证，再由论证生成完整正文。

## 解读结构

综合解读只显示：

1. 最终判断；
2. 局势总解；
3. 关键牌位详解；
4. 成立、失败与转折条件；
5. 时间与表现形式，仅在多牌牌阵提供结果或趋势证据时显示。

不得显示或换名恢复：问题复述、机械走势播报、牌阵故事、牌间对话、留意事项、三步建议和固定追问。

## 论证模型

每次解读先建立以下结构：

- 问题领域与现实主体；
- 形成原因；
- 当前状态；
- 核心矛盾；
- 推动力与阻力；
- 行动转折；
- 结果落点；
- 成立条件、失败条件与转折信号；
- 可选的出现渠道、速度、顺序与兑现信号。

每个正文段落必须提供新的判断，并绑定具体牌位。牌名只出现在牌位标题中，正文不得重复念牌名。

## 内容量

| 牌阵 | 用户可见正文范围 |
|---|---:|
| 单牌 | 420–1300字 |
| 时间线 | 850–2200字 |
| 五牌十字 | 1250–3400字 |
| 凯尔特十字 | 2100–5600字 |

长度只是下限门禁，不能通过复述问题、牌名、位置名称或同义句凑字。

## 去重与措辞门禁

- 禁止用户问题原文出现在解读正文；
- 禁止“走势从……起步”“作为状态线索时指出”等机械句；
- 禁止“可能、也许、或许、倾向、继续观察”等模糊词；
- 任意两段二元字符相似度不得达到0.72；
- 三项条件必须针对本次问题领域与牌面证据生成；
- 最终判断仍为唯一决断，不允许 `indeterminate`。

## 性能边界

- 模块 Worker 在应用初始化后后台预热；
- 78张牌和90题资料只在 Worker 内预载一次；
- UI向 Worker发送轻量可序列化输入，不传完整资料对象；
- 单牌与综合标签只渲染当前视图；生成过的节点按本次占卜缓存；
- 通过 `DocumentFragment` 和 `replaceChildren` 一次提交DOM；
- 长篇屏外区块使用 `content-visibility` 和 CSS containment；
- 凯尔特长篇生成中位数低于20ms，P95低于50ms；
- 同一页面生命周期只创建一个推理 Worker。
