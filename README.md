# 星纱塔罗 · 离线塔罗占卜模拟器

星纱塔罗是一款完全在本机运行的中文塔罗牌 GUI。它提供自由问题、四种牌阵、四套完整牌面、结构化规则解读、本地历史和 PWA 离线能力。

项目运行时不调用 AI 大模型、在线推理 API 或生成式服务。浏览器负责界面、抽牌、解读、历史与缓存，Python 标准库只负责启动本地服务，不需要安装第三方 Python 包。

> 当前 `main` 是 Phase 14 / V3 主线快照，已经与 2.1.0 的固定问题和期待契合流程有明显区别。正式版本号与最终发布验证尚待另行确定，因此本文不再把 2.1.0 当作当前主线版本。

## 当前主线与 2.1.0 的主要区别

| 项目 | 2.1.0 旧流程 | 当前 V3 主线 |
|---|---|---|
| 提问方式 | 六大主题、90 个固定问题 | 2–200 字符自由问题 |
| 问题用途 | 参与问题类型与期待策略 | 只用于页面标题和本地历史 |
| 解读输入 | 固定问题、期待、判断标准等 | 只读取牌阵、牌面、牌位与正逆位 |
| 评分方式 | 按问题类型决定是否评级 | 四种牌阵统一输出结构化顺势等级 |
| 多牌阵权重 | 多因素相对平均 | 结果因素占 60%，其余因素合计 40% |
| 历史格式 | V1 / V2 | 新记录使用 V3，并只读兼容 V1 / V2 |
| 牌阵定义 | V1 牌位语义 | V2 独立牌阵定义与关系图 |

旧版记录不会被原地重评分或改写。V1、V2 和 V3 历史可以合并读取，同一记录存在多个投影时优先使用结构化程度更高的新格式。

## 主要功能

- 完整 78 张结构化塔罗牌资料与正逆位语义。
- 自由问题输入，支持 2–200 个 Unicode 字符。
- 四种牌阵：
  - 单张牌，1 张
  - 时间之流，3 张
  - 五牌十字，5 张
  - 凯尔特十字，10 张
- 四套完整牌面：
  - Rider–Waite–Smith
  - 阿尔诺古典
  - 瑞士 1JJ
  - Solesio 皮埃蒙特
- 原生规则解读链：`SpreadReadingProfile → Observation → Relation → Claim → Assessment → Presentation`。
- 单牌详情与整副牌阵综合判断分开展示。
- 抽牌、正逆位和界面渲染使用独立、可重放的随机流。
- IndexedDB 本地历史、导入导出、校验、删除和容量降级。
- V1 / V2 历史只读兼容，V3 新记录保留牌阵定义与随机版本信息。
- Worker 负责解读计算，失败时保留原牌并允许恢复，不在主线程静默执行另一套结果。
- PWA 离线缓存、受控更新、上一完整版本回滚和牌组按需缓存。
- 键盘操作、焦点管理、屏幕阅读器支持、错误恢复与脱敏诊断。

## 提问与解读边界

自由问题只用于帮助用户组织思路，并保存在本地历史中。问题正文不会进入以下环节：

- 洗牌与抽牌
- 正逆位决定
- Observation、Relation 和 Claim
- 综合评分与等级
- 随机种子与重放
- 诊断正文

因此，修改问题措辞不会改变同一随机状态下的牌面或规则结果。当前系统也不再提供固定问题、主题分类、期待结果、判断标准、时间范围或双路径比较入口。

## 顺势等级

四种牌阵统一使用 `SSS、SS、S、A、B、C、D、E` 八个等级表达牌阵结构与当前走势的顺逆程度。

等级不是未来事件的发生概率，也不是对用户愿望的自动迎合。它来自牌面、牌位、正逆位、关系和冲突形成的结构化证据。

多牌阵评估包含：

- 基础条件
- 过程状态
- 结果方向
- 稳定性
- 阻力
- 代价
- 可控性
- 牌间冲突

时间之流、五牌十字和凯尔特十字的结果因素权重为 **60%**，其他因素合计 **40%**。过程、阻力、代价和冲突仍会限制最终等级，因此不会出现只看最后一张牌、前面一地狼藉却照样评为顶级的荒唐结果。

单张牌没有独立结果位，使用自己的五因素权重，部分因素标记为不适用，最高等级为 `S`。

## 启动

### Windows

最简单的方式：

1. 双击 `启动星纱塔罗.bat`。
2. 应用会在默认浏览器中打开。
3. 关闭最后一个应用页面后，本地服务会自动退出。

### 终端

```powershell
git clone https://github.com/AAAYNMMM/astra-tarot-simulator.git
cd astra-tarot-simulator
python run.py
```

默认监听本机端口 `57321`。端口被占用时会自动选择空闲端口。

```powershell
python run.py --no-browser
python run.py --port 0
```

- `--no-browser`：只启动服务，不自动打开浏览器。
- `--port 0`：直接使用系统分配的空闲端口。

## 使用流程

1. 写下想梳理的问题。
2. 选择牌阵和牌面。
3. 开始洗牌与发牌。
4. 逐张翻牌，或在发牌完成后全部翻开。
5. 在“单牌”标签查看牌位与单张牌义。
6. 在“综合”标签查看整副牌阵的结构判断与顺势等级。
7. 需要时从本地历史中重新查看或导出记录。

快捷键：

- `Ctrl + Enter`：在准备页开始占卜。
- `R`：发牌完成后翻开全部牌。

## 离线、隐私与本地数据

应用运行时不会上传问题、牌面、解读、历史、随机种子或诊断正文。所有记录与设置均由浏览器本地存储管理。

首次运行只准备应用壳和必要知识资料，不会阻塞式下载四套完整牌面。牌组可以在界面中按需缓存、查看进度、估算空间并单独删除。

清除浏览器站点数据会删除本地历史、设置和缓存。重要记录应先通过应用内功能导出。

塔罗内容用于自我觉察、叙事探索和娱乐，不替代医疗、法律、投资或其他专业意见。

## 技术结构

项目没有强制前端构建步骤，运行时使用原生 ES Modules。

```text
浏览器界面
  ├─ 自由问题与牌阵设置
  ├─ 洗牌、发牌、翻牌动画
  ├─ Worker 解读请求
  ├─ 单牌与综合展示
  ├─ IndexedDB 历史
  └─ Service Worker / PWA

规则引擎
  ├─ SpreadReadingProfile
  ├─ SpreadObservation
  ├─ SpreadRelation
  ├─ SpreadClaim
  ├─ StructuralAssessment
  └─ ReadingPresentation

本地服务
  └─ Python 标准库 HTTP 服务与生命周期管理
```

V3 Worker 使用严格请求合同。自由问题、期待、比较条件和其他旧字段不会被传入解读引擎，未知字段会被拒绝，而不是悄悄参与结果。

## 开发与验证

需要 Node.js 和 Python 3。

```powershell
npm run test:v3
npm run test:full
python automation/validate.py --scope full
python scripts/doctor.py
```

常用范围：

- `npm run test:v3`：自由问题隔离、四牌阵 V3、随机重放和历史兼容。
- `npm run test:full`：完整项目验证入口。
- `python automation/validate.py --scope full`：跨模块全量门禁。
- `python scripts/doctor.py`：环境与项目状态检查。

项目不依赖 GitHub Actions 作为发布结论。正式发布验证由 CWapi 本地 Runner 对固定 40 位 commit 执行，避免拿别的工作区、别的提交或一份心情良好的日志冒充当前版本通过。

当前实施状态与已完成验证见：

- [`docs/EXECUTION_CONTRACTS.md`](docs/EXECUTION_CONTRACTS.md)
